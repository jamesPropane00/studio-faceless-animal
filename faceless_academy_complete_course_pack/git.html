1. Repository model

Understand working tree, staging area, and commit history.

Core knowledge

  • git status explains current state.
  • git add stages selected changes.
  • git commit records a snapshot.
  • A commit has a parent relationship and identifier.
git status
git add .
git commit -m "Describe the change"

2. Branches

Develop without disrupting main.

Core knowledge

  • A branch is a movable name pointing to a commit.
  • git switch -c creates and switches.
  • Merging combines histories.
  • Rebase reapplies commits onto a new base and rewrites commit identities.
git switch -c feature/login

3. Remotes

Exchange commits with remote repositories.

Core knowledge

  • fetch downloads remote objects and refs.
  • pull normally fetches then integrates.
  • push uploads local commits.
  • origin is a conventional remote name.
git fetch origin
git pull --rebase
git push

4. Undoing changes

Choose safe recovery tools.

Core knowledge

  • restore can discard working-tree edits.
  • restore --staged unstages while preserving edits.
  • revert creates a new inverse commit.
  • reset can move a branch and may rewrite local history.
git restore --staged file.txt
git revert abc123

5. Conflicts

Resolve competing changes.

Core knowledge

  • Open conflicted files and inspect markers.
  • Choose correct combined content.
  • Stage resolved files.
  • Continue or commit the operation.

Practice Exam

These are original exam-style questions, not copied test items.

1. Which command unstages a file but keeps its edits?

restore --staged removes it from the index without deleting the edit.

2. Which command is safest on shared history?

revert preserves history by adding an inverse commit.

3. What does git fetch do?

fetch updates remote-tracking information.

4. Which command creates and switches branches?

switch -c creates and checks out the branch.

5. What is a commit?

A commit records a snapshot and metadata.
