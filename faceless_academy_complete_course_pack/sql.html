1. Relational foundations

Understand tables, keys, and relationships.

Core knowledge

  • A primary key uniquely identifies a row.
  • A foreign key references another table.
  • Normalization reduces harmful redundancy.
  • NULL represents missing or unknown data.

2. Queries and filtering

Retrieve exact records.

Core knowledge

  • SELECT chooses columns.
  • WHERE filters rows before grouping.
  • ORDER BY sorts results.
  • LIMIT restricts returned rows in many systems.
SELECT name, salary FROM employees WHERE active = TRUE ORDER BY salary DESC;

3. Joins

Combine related tables.

Core knowledge

  • INNER JOIN returns matched rows.
  • LEFT JOIN keeps every left-side row.
  • Join conditions usually compare key columns.
  • A many-to-many relationship uses a junction table.
SELECT o.id, c.name FROM orders o JOIN customers c ON c.id=o.customer_id;

4. Aggregation

Summarize data.

Core knowledge

  • COUNT(*) counts rows.
  • GROUP BY creates groups.
  • HAVING filters groups after aggregation.
  • Aggregate functions generally ignore NULL except COUNT(*).
SELECT department, AVG(salary) FROM employees GROUP BY department HAVING AVG(salary)>70000;

5. Transactions and indexes

Reason about consistency and speed.

Core knowledge

  • ACID describes transaction properties.
  • COMMIT makes a transaction durable.
  • ROLLBACK cancels uncommitted changes.
  • Indexes speed reads but cost storage and write overhead.

Practice Exam

These are original exam-style questions, not copied test items.

1. Which clause filters grouped results?

HAVING applies after GROUP BY.

2. Which join keeps all left-table rows?

LEFT JOIN preserves unmatched left rows.

3. What does COUNT(*) count?

COUNT(*) counts rows.

4. Which command permanently accepts a transaction?

COMMIT makes the transaction changes durable.

5. A foreign key primarily enforces what?

It helps ensure referenced records exist.
